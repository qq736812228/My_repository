# 继续完成记录 V2

本轮在原始整合工程包基础上继续补齐生产化联调和后台可用性问题，重点不是增加演示文件，而是修复会影响真实运行的链路缺陷。

## 后端

- 修复 `InvitationRepository` 派生查询字段错误，避免 Spring Data JPA 启动阶段校验失败。
- 新增 `EntityPatchUtil`，管理端 PUT 更新改为非空字段补丁式更新，避免通用 CRUD 表单遗漏字段时把关系、密码或审计字段覆盖为空。
- `BaseController.currentUserId()` 改为严格鉴权，未登录访问用户私有数据返回 401；首页、团体客户、合作伙伴、商户申请等公共入口改为 `optionalUserId()`。
- `AuthFilter` 增加 ADMIN 角色校验，普通小程序用户 Token 无法访问 `/api/admin/**`。
- 新增 `/api/admin/me`，返回当前后台用户、角色、菜单和权限码。
- 新增角色分配菜单接口：`PUT /api/admin/roles/{id}/menus`。
- `GlobalExceptionHandler` 增强 401、403、404、409、502 的 HTTP 状态映射。
- 新增 `WechatProperties`、`WechatService`，微信登录支持生产 `jscode2session` 和开发兜底模式。
- 微信支付服务升级为 JSAPI 预下单 + RSA 签名参数生成，生产可通过环境变量配置商户号、证书序列号、PKCS8 私钥和回调地址。
- 支付回调落库后会同步更新商城订单支付状态、支付渠道和交易流水号。

## 管理端

- 新增 `crudSchemas.ts`，所有后台 CRUD 页面使用明确字段、中文标签和输入控件，不再依赖首行数据推断字段。
- 新增字典管理、行政区划、订单明细、支付回调、消息管理、AI 报告等菜单入口。
- Axios 响应拦截器增加 401/403 自动清理 Token 并跳转登录。

## 小程序端

- 请求封装增加 401 自动跳转登录、403 友好提示。
- 注册 / 登录页补充注册流程，支持账号注册后直接登录。
- 首页仍支持未登录浏览；档案、检测、积分、下单、支付等私有数据操作要求登录。

## 文档与配置

- 部署文档补充微信登录、微信支付和生产环境变量。
- 接口联调文档补充后台当前账号、角色菜单分配、字典/行政区、订单明细、支付回调、AI 报告等端点。
- Docker Compose 增加微信支付生产变量占位。
